# Roomly

Roomly — клиент-серверное приложение для бронирования переговорных комнат.
Проект подготовлен для домашнего задания: есть фронтенд, Go-бэкенд,
PostgreSQL, авторизация, CRUD-операции и бизнес-логика проверки пересечений
бронирований. В приложении есть роли: администратор управляет комнатами и всеми
бронированиями, обычный пользователь бронирует комнаты и видит только свои
записи.

## Запуск через Docker Compose

1. Скопируйте пример переменных окружения:

   ```bash
   cp .env.example .env
   ```

2. Запустите PostgreSQL:

   ```bash
   docker compose up -d db
   ```

3. Примените миграцию:

   ```bash
   docker compose run --rm app migrate
   ```

4. Запустите приложение:

   ```bash
   docker compose up --build app
   ```

5. Откройте приложение:

   ```text
   http://localhost:8080
   ```

## Тестовый пользователь

После миграции доступен демонстрационный пользователь:

```text
Логин: admin
Пароль: admin123
Роль: администратор
```

Новые пользователи, созданные через регистрацию, получают роль обычного
пользователя.

## API

- `GET /healthz` — проверка доступности сервера.
- `POST /api/login` — вход в систему.
- `POST /api/register` — регистрация пользователя.
- `POST /api/logout` — выход из системы.
- `GET /api/me` — текущий пользователь.
- `PUT /api/password` — смена пароля текущего пользователя.
- `GET /api/rooms` — список переговорных комнат.
- `POST /api/rooms` — создание комнаты.
- `PUT /api/rooms/{id}` — обновление комнаты.
- `DELETE /api/rooms/{id}` — удаление комнаты.
- `GET /api/bookings` — список бронирований.
- `POST /api/bookings` — создание бронирования.
- `PUT /api/bookings/{id}` — обновление бронирования.
- `DELETE /api/bookings/{id}` — удаление бронирования.

Все маршруты `/api/*`, кроме `/api/login`, требуют авторизации через cookie
сессии. Маршрут `/api/register` также доступен без авторизации.

Пример тела запроса для регистрации:

```json
{
  "username": "ivan",
  "password": "secret123"
}
```

Пример тела запроса для смены пароля:

```json
{
  "currentPassword": "secret123",
  "newPassword": "newsecret123"
}
```

Пример тела запроса для комнаты:

```json
{
  "name": "Альфа",
  "capacity": 8,
  "location": "2 этаж"
}
```

Пример тела запроса для бронирования:

```json
{
  "roomId": 1,
  "purpose": "Планёрка команды",
  "startsAt": "2026-10-02T09:00:00Z",
  "endsAt": "2026-10-02T10:00:00Z"
}
```

## Структура

- `backend/` — Go-бэкенд.
- `backend/app.go` — сборка HTTP-приложения и маршрутов.
- `backend/auth.go`, `backend/room.go`, `backend/booking.go` — обработчики и
  бизнес-правила по доменным областям.
- `backend/migrate.go` — запуск SQL-миграций.
- `web/index.html` — разметка интерфейса.
- `web/styles.css` — стили интерфейса.
- `web/app.js` — API-клиент, состояние страницы, рендер и обработчики событий.
- `migrations/` — SQL-миграции, выполняются по имени файла в порядке
  возрастания.

## Архитектура

Приложение построено как клиент-серверная система. Фронтенд обращается к
бэкенду через REST API.

Бэкенд имеет простую слоистую структуру:

- `main.go` — запуск процесса, конфигурация, подключение к PostgreSQL;
- `app.go` — HTTP-приложение и маршрутизация;
- доменные HTTP-обработчики — авторизация, комнаты, бронирования;
- `migrate.go` и `migrations/` — управление схемой базы данных.

Фронтенд разделён на View/State/API:

- `index.html` — View-разметка;
- `styles.css` — визуальное оформление;
- `app.js` — API-клиент, состояние интерфейса, рендеринг списков и обработка
  действий пользователя.
