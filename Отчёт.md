# Отчёт

## Задание

В рамках задания приложение Roomly было подготовлено к запуску в однодовой
инсталляции Kubernetes через minikube.

Roomly — веб-приложение для бронирования переговорных комнат. Приложение
состоит из Go-бэкенда, статического HTML/CSS/JavaScript-интерфейса и базы
данных PostgreSQL.

## Docker-образ

Для приложения используется Dockerfile в корне проекта. Образ собирает Go-сервер
и копирует в контейнер статические файлы интерфейса и SQL-миграции.

Используемый образ:

```text
meeting-rooms:v1
```

Команды сборки и загрузки образа в minikube:

```bash
eval $(minikube docker-env)
docker build -t meeting-rooms:v1 .
minikube image load meeting-rooms:v1
```

## Использованные Kubernetes-абстракции

Для запуска приложения используются следующие абстракции Kubernetes:

- `Namespace` `meeting-rooms` — отдельное пространство имен для ресурсов
  приложения.
- `ConfigMap` `rooms-config` — хранит некритичную конфигурацию: имя
  пользователя PostgreSQL, имя базы данных и порт приложения.
- `Secret` `rooms-secret` — хранит пароль PostgreSQL и строку подключения
  `DATABASE_URL`.
- `PersistentVolumeClaim` `postgres-data` — выделяет постоянное хранилище для
  данных PostgreSQL.
- `Deployment` `postgres` — запускает контейнер PostgreSQL.
- `Service` `postgres` типа `ClusterIP` — предоставляет базе данных стабильное
  DNS-имя внутри кластера.
- `Job` `rooms-migrate` — один раз применяет SQL-миграции приложения.
- `Deployment` `rooms-app` — запускает контейнер с веб-приложением.
- `Service` `rooms-app` типа `ClusterIP` — предоставляет приложению стабильное
  имя внутри кластера. Для демонстрации UI на локальной машине используется
  `kubectl port-forward`.
- `readinessProbe` и `livenessProbe` — проверяют готовность и работоспособность
  контейнеров.

## Взаимодействие сервисов приложения

Пользователь открывает приложение через сервис `rooms-app`. Этот сервис
направляет HTTP-запросы на поды `Deployment/rooms-app` по порту `8080`.

Контейнер `rooms-app` обслуживает:

- статический UI из папки `web/`;
- REST API по маршрутам `/api/*`;
- проверку состояния по маршруту `/healthz`.

Приложение подключается к PostgreSQL через переменную окружения `DATABASE_URL`.
В строке подключения используется DNS-имя Kubernetes-сервиса `postgres`:

```text
postgres://meeting_user:meeting_local_password@postgres:5432/meeting_rooms?sslmode=disable
```

Это означает, что приложение обращается не к конкретному IP-адресу пода базы, а
к сервису `postgres`, который перенаправляет трафик на актуальный под
PostgreSQL.

Перед запуском приложения выполняется `Job` `rooms-migrate`. Он использует тот
же Docker-образ `meeting-rooms:v1`, но запускает команду:

```bash
./server migrate
```

Миграции создают таблицы пользователей, сессий, переговорных комнат и
бронирований, а также демонстрационного администратора.

## Команды запуска

Запуск minikube:

```bash
minikube start
```

Сборка и загрузка образа:

```bash
eval $(minikube docker-env)
docker build -t meeting-rooms:v1 .
minikube image load meeting-rooms:v1
```

Применение манифестов:

```bash
kubectl apply -f k8s/00-namespace.yaml
kubectl apply -f k8s/01-configmap.yaml
kubectl apply -f k8s/02-secret.yaml
kubectl apply -f k8s/03-postgres.yaml
kubectl wait -n meeting-rooms --for=condition=available deployment/postgres --timeout=120s
kubectl apply -f k8s/04-migration-job.yaml
kubectl wait -n meeting-rooms --for=condition=complete job/rooms-migrate --timeout=120s
kubectl apply -f k8s/05-app.yaml
kubectl wait -n meeting-rooms --for=condition=available deployment/rooms-app --timeout=120s
```

Проверка запущенных подов и ресурсов:

```bash
kubectl get all -n meeting-rooms
kubectl get pods -n meeting-rooms -o wide
```

Открытие UI приложения на локальной машине:

```bash
kubectl port-forward -n meeting-rooms service/rooms-app 8080:8080
```

После запуска port-forward приложение доступно в браузере по адресу:

```text
http://localhost:8080
```

Масштабирование приложения:

```bash
kubectl scale deployment/rooms-app -n meeting-rooms --replicas=3
kubectl get pods -n meeting-rooms
```

## Данные для демонстрации

После выполнения миграций доступен демонстрационный пользователь:

```text
Логин: admin
Пароль: admin123
```

В UI можно показать вход в систему, просмотр комнат, создание комнаты и создание
бронирования.

## Использованные файлы

- `Dockerfile` — сборка Docker-образа приложения.
- `k8s/00-namespace.yaml` — namespace.
- `k8s/01-configmap.yaml` — конфигурация приложения.
- `k8s/02-secret.yaml` — секреты.
- `k8s/03-postgres.yaml` — PostgreSQL, PVC и сервис базы.
- `k8s/04-migration-job.yaml` — запуск миграций.
- `k8s/05-app.yaml` — deployment и service приложения.
