# Отчёт по заданию: Grafana dashboard

## Развёртывание и источники данных

Grafana запущена в кластере minikube в namespace `monitoring`. В качестве источника данных добавлена VictoriaMetrics через совместимый с Prometheus HTTP API:

`http://vm-single-victoria-metrics-single-server.monitoring.svc.cluster.local:8428`

В Grafana источник данных отображается как `prometheus-1`. Он собирает метрики приложения `meeting-rooms`, synthetic-пробера и PostgreSQL Exporter.

## Dashboard приложения

Создан dashboard **Meeting Rooms — SLA & Runtime**. В нём использованы подходы RED и Golden Signals: доступность, частота запросов, ошибки и показатели потребления ресурсов.

![Dashboard приложения](dashboard-app.png)

| Панель | Метрика / запрос | Зачем нужна |
|---|---|---|
| Приложение доступно | `up{app="rooms-app"}` | Показывает, доступно ли приложение для VictoriaMetrics. Значение `1` означает успешный scrape. |
| RPS бизнес-операций | `sum(rate(business_operation_attempts_total{app="rooms-app"}[1m]))` | RED: частота бизнес-операций в секунду. Позволяет оценить текущую нагрузку. |
| Ошибки создания комнат | `sum(rate(business_operation_attempts_total{app="rooms-app",operation="room_create"}[5m])) - sum(rate(rooms_created_total{app="rooms-app"}[5m]))` | RED: число неуспешных операций создания комнат в секунду. |
| SLA synthetic-пробера, % | отношение `increase(probe_cycles_success_total)` к `increase(probe_cycles_total)` за выбранный период | Отдельная панель SLA. Пробер выполняет полный пользовательский сценарий: вход, создание комнаты, создание и удаление бронирования. Целевое значение SLO — 99%; на скриншоте SLA равен 100%. |
| Горутины Go | `go_goroutines{app="rooms-app"}` | Метрика рантайма Go: рост числа горутин помогает заметить утечки или деградацию. |
| Heap-память Go, MiB | `go_memstats_alloc_bytes{app="rooms-app"} / 1024 / 1024` | Метрика рантайма Go: объём занятой heap-памяти, помогает отслеживать использование ресурсов. |

Для панели SLA настроены пороги: ниже 99% — проблемное состояние, от 99% — нормальное. На момент демонстрации synthetic-пробер завершал все циклы успешно.

## PostgreSQL Exporter

Импортирован dashboard **PostgreSQL Database** из каталога Grafana.com (ID `9628`). В качестве datasource выбран VictoriaMetrics (`prometheus-1`). Dashboard получает данные из `postgres-exporter`, запущенного рядом с PostgreSQL в кластере.

![Dashboard PostgreSQL Exporter](dashboard-postgres.png)

На dashboard отображаются версия PostgreSQL, активные сессии, транзакции, чтение/запись данных, CPU, память и открытые файловые дескрипторы. Наличие заполненных графиков и значений подтверждает успешную работу импортированного dashboard.

## Приложенные артефакты

- `meeting-rooms-dashboard.json` — экспорт dashboard приложения из Grafana;
- `dashboard-app.png` — скриншот dashboard приложения;
- `dashboard-postgres.png` — скриншот импортированного dashboard PostgreSQL Exporter;
- короткий скринкаст с демонстрацией dashboard приложения и PostgreSQL dashboard записывается отдельно.
